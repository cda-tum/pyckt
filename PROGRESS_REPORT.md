**Author:** Firas

---

## 1. Goal

Translate the acst C++ analog-circuit-synthesis tool (~112 k lines of C++) into a
maintainable Python package (**pyckt**), reproducing the same six analysis modes
and — as far as possible — the **same outputs** so the Python tool can be
validated against the original. acst is the reference: for any given input, pyckt
should produce functionally equivalent results.

reference rather than by eye. Recognition and partitioning are additionally
validated at scale against the **FUBOCO Gallery** — 2 886 reference circuits
generated by a newer acst build.

## 4. Results — pyckt vs acst

Same input bundles on both tools; acst is the reference. Full detail and exact
per-mode commands in [`report/comparison/COMPARISON_REPORT.md`](report/comparison/COMPARISON_REPORT.md).
Side-by-side outputs in [`report/samples/`](report/samples/).

### 4.1 structrec — ✅ exact match
- **16/16** leaf devices in the same structure; **16/16** in the same top-level
  composite; full hierarchy type-count identical.
- **At scale: 2 886/2 886** gallery circuits semantically identical.
- Samples: [`report/samples/structrec/`](report/samples/structrec/).

### 4.2 partitioning — ✅ exact match
- **19/19** devices in the same section; the full gm-path/stage decomposition
  matches (firstStage / primary+secondary secondStage / loadParts / biasParts /
  capacitances).
- **At scale: fd-1-2 936/936 identical, s-1-2 1 949/1 950** — the single residual
  is one gm-label on a composite that only the newer acst library can classify.
- No longer needs `--circuit-params`: input/output/bias nets are inferred from
  the structure (as acst does).
- Samples: [`report/samples/partitioning/`](report/samples/partitioning/).

### 4.3 rulegen — ✅ exact match
- Emits the acst `pairLibrary` artifact (top-level library + per-item XML with
  full `pairConnection`/`characteristicConnection`/`recognitionRules`).
- **10/10** items, **10/10** hierarchy levels, **10/10** persistence values —
  item-for-item, on acst's own input library.
- Samples: [`report/samples/rulegen/`](report/samples/rulegen/).

### 4.4 automaticsizing — ✅ format + model match; endpoint is acst's own variance

**Solver background — CP-SAT:** searches a discrete grid of W/L for an assignment
satisfying all circuit constraints (KCL, operating region, gain/Ft/PM/power/area
targets). acst uses Gecode branch-and-bound; pyckt uses OR-Tools CP-SAT — same
paradigm, different engine.

- **Schema: fully 1:1.** Every section and field acst emits is now produced —
  `ExpectedPerformance` (incl. `TransitFrequencyWithErrorFactor`, `CMRR`,
  `negPSRR`/`posPSRR`, common-mode input range), `Voltages`, `Currents`,
  `Dimensions` (transistors + capacitors), plus a sized HSPICE netlist.
- **Performance model validated.** Evaluated on *acst's own solved design*
  (its W/L, our model) the numbers reproduce acst's to ~1–4 %:

  | Metric | acst | pyckt model | error |
  |--------|-----:|-----:|--:|
  | Gain (dB) | 90.0 | 90.3 | +0.4 % |
  | Transit freq (MHz) | 6.93 | 6.87 | −0.9 % |
  | Slew rate (V/µs) | 22.5 | 22.8 | +1.1 % |
  | CMRR (dB) | 133 | 133 | **0.0 %** |
  | Power (mW) | 6.12 | 6.12 | 0 % |
  | Area (µm²) | 10 868 | 10 868 | 0 % |

- **The endpoint difference is not a defect.** Re-running the *same acst binary
  on the same inputs* produced a design differing from its own earlier reference
  by up to **63 %** (power) with per-device ΔW averaging 107 % — acst's optimiser
  branches on random W/L and stops at a wall-clock budget, so its numbers are a
  search artifact, not a fixed target. pyckt meets every spec, with no device
  stuck at the minimum-size floor. (Full analysis:
  [`report/reports/SIZING_CONVERGENCE.md`](report/reports/SIZING_CONVERGENCE.md).)
- Samples: [`report/samples/sizing/`](report/samples/sizing/).

### 4.5 toplibgen — ✅ full parity
- `--output-format acst` emits the acst directory layout with real ACST-format
  netlists.
- **3 912/3 912 distinct topologies** (device-for-device), and **exact
  file-level parity** per category (SingleOutput 2 940, FullyDifferential 936,
  Complementary 36).

### 4.6 synthesis — ✅ comparable
- Filters → sizes each candidate with the **real CP-SAT sizing solver** → ranks
  on solved performance (gain/Ft/slew/power/area/PM) → writes fully-sized
  netlists.
- Against acst's reference (868 sized designs, captured by a ~3 h acst run):
  pyckt sized **2 836 candidates covering 863/868 (99.4 %)** of acst's
  topologies — the last 5 are budget-timeouts (they size with a longer budget),
  **zero provable-infeasible drops**. Top-ranked candidates meet every spec.
- Samples: [`report/samples/synthesis/`](report/samples/synthesis/) (ranking JSON + a sized
  top candidate).

## 5. What changed this reporting period

The recognition/rule modes moved from "close" to **exact and validated at
scale**; sizing and the two generators went from "framework" to **real,
comparable output**. Concretely, a full acst-vs-pyckt comparison across all six
modes was run, and every gap it surfaced was fixed:

- **structrec/partitioning:** validated across the 2 886-circuit FUBOCO Gallery;
  fixed mixed-tech labeling, four newer-acst composite items, device ordering,
  load/gm/bias/capacitor classification (reached full gallery parity bar one
  circuit).
- **rulegen:** hierarchy-level and persistence now match item-for-item; the
  loader accepts acst's own wrapper library file.
- **automaticsizing:** completed the XML schema (net voltages, capacitors,
  CMRR/PSRR, common-mode range); fixed the performance model (cascode gain
  composition, mirror-factor Ft, output-branch slew, supply-current power) —
  validated to ~1 % against acst's design; added the common-mode-range
  constraint.
- **toplibgen:** de-duplicated the acst-format emission to exact file-level
  parity.
- **synthesis:** replaced the placeholder scoring with the real sizing pipeline;
  added two-stage gain composition (A₁·A₂), which lifted coverage of acst's
  topologies from 92 % to 99.4 %.

Every gap found is tracked as a GitHub issue with a merged or open PR (#30–#61).

## 6. Remaining work

1. **Sizing operating point (optional):** the endpoint differs from any single
   acst run but sits within acst's own run-to-run spread; matching a specific
   acst design would mean reproducing its randomized search trajectory, which
   isn't a well-defined target. The faithful targets — schema, model, and spec
   satisfaction — are met.
2. **synthesis budget/coverage:** a handful of candidates need a longer
   per-candidate CP-SAT budget to size; a full-coverage run is a time knob, not
   a code gap.
3. **One gallery residual:** a single `s-1-2` partitioning circuit carries a
   gm-label only the newest acst library can produce.

## 7. How to reproduce

Exact per-mode commands (acst and pyckt) are in
[`report/comparison/COMPARISON_REPORT.md` §0](report/comparison/COMPARISON_REPORT.md). In short:

```bash
PYCKT="/home/jrad/pyckt/pyckt/.venv/bin/python -m cli"   # from the repo root
# structure recognition in acst-compatible output:
$PYCKT structrec --circuit input.ckt --device-types deviceTypes.xcat \
   --mapping HSpiceMapping.xcat --supply-nets supplyNets.xcat \
   --output-format acst --output structrec_pyckt.xml
```
